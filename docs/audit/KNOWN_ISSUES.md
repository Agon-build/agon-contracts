# Known issues before external review

Found by our own reading during audit preparation (2026-11-26). Each gets a
fix with a test that failed first, or a recorded decision. The PRE IDs map to
F IDs once the Arc Studio review numbers its findings.

| ID | Severity (ours) | Contract | Issue | Plan |
| --- | --- | --- | --- | --- |
| PRE-01 | Medium, **Fixed** | AgonProfileRegistry | `suspendProfile` accepts an Archived profile, and `reinstateProfile` then returns it to Active. Archiving is meant to be final (the function's own comment says "Archived stays archived"), but the admin can undo it in two steps | Fixed: `suspendProfile` only from Active (`ProfileNotActive`). Tests `test_archived_profile_cannot_be_suspended_or_reinstated`, `test_suspend_twice_is_refused` in `test/AuditFixes.t.sol` |
| PRE-02 | High, **Fixed** | AgonJobEscrowV2, AgonPrizeVault | Every payout is pushed with `safeTransfer`. If a provider, buyer, treasury or sponsor is blocklisted on Arc, the transfer reverts and the job or pool can never settle: `acceptSubmission`, `autoAccept`, `resolveDispute`, `claimRefundAfterRejection`, `exitStaleDispute`, `failJob`, `refundRemaining`, `refundUnpublished` all revert. A blocked treasury freezes every escrow settlement that carries a fee | Fixed (D3): every payout goes through `_send`, which credits the amount to `credits[to]` when the transfer fails, and the job or pool still settles; `withdrawCredit()` pays only the caller. A blocked address cannot send transactions on Arc, so `failJob` and `claimRefundAfterRejection` are now open to anyone once their window passes (the money still goes only to the buyer). Tests in `test/AgonJobEscrowV2.Payouts.t.sol` and `test/AgonPrizeVault.Payouts.t.sol` |
| PRE-03 | Low, **Fixed** | AgonArena | Anyone can call `expireEvaluation` on a Submitted evaluation once `expiresAt` passes, even though the participant has already delivered and only the evaluator's score is missing. Pause also does not extend `expiresAt` | Fixed (owner decision 2026-11-26): `expireEvaluation` applies only to Pending and Active; a Submitted evaluation waits for its score. Pause still does not extend `expiresAt`, which now only affects evaluations without evidence. Tests `test_submitted_evaluation_cannot_be_expired`, `test_pending_and_active_evaluations_still_expire` |
| PRE-04 | Low, **Fixed** | AgonProfileRegistry | The constructor does not refuse a zero admin or a zero identity registry | Fixed: `ZeroAddress`. Test `test_profile_registry_refuses_zero_addresses` |
| PRE-05 | Test gap, **Done** | AgonJobEscrowV2, AgonArena | Their tests deployed the V1 registry, not the V2 registry they are deployed against | Done: `test/AgonJobEscrowV2.t.sol` and `test/AgonArena.t.sol` now deploy `AgonServiceRegistryV2` and verify with `setVerificationForVersion` |
| PRE-06 | Test gap, **Done** | All | No fuzz or invariant tests; branch coverage 24 to 56 percent; three pause tests read cached time under coverage (see `BASELINE.md`). The gas test now checks that a commit touches no storage | Fuzz tests added (Task 6): `test/AgonJobEscrowV2.Fuzz.t.sol`, `test/AgonPrizeVault.Fuzz.t.sol`, `test/Registries.Fuzz.t.sol`, `test/AgonArena.Fuzz.t.sol`, 1,000 runs each. The three pause tests now use absolute times. Invariant tests added (Task 7): `test/invariant/`, 15 invariants over escrow, vault, registry and profiles, 512 runs (depth 200 for escrow and vault, 50 for the registry), with pauses, fee and treasury changes, new versions and blocklisted addresses in the sequences. Branch coverage is Task 9 |
| PRE-07 | Product, **Done** | AgonJobEscrowV2 | A rejected job's refund waits 7 days even when the provider agrees | Done (D4): `acceptRejection(jobId)`, provider only, from Rejected, works while paused. Tests in `test/AgonJobEscrowV2.Payouts.t.sol` |
| PRE-08 | Informational, **Fixed** | AgonJobEscrowV2 | `openDispute` reverted with `NotBuyer` for a caller who is neither party, although the provider may also call it | Fixed: reverts `NotParty`, as `exitStaleDispute` does. Test `testFuzz_onlyPartiesAct` in `test/AgonJobEscrowV2.Fuzz.t.sol` |
| PRE-09 | Low, **Fixed** | AgonPrizeVault | At exactly the claim deadline both `claim` and `refundRemaining` were allowed, so anyone could close the pool and send the unclaimed principal to the sponsor in the same second a winner could still claim. Every other window in the escrow and the vault is strict on one side | Fixed: `refundRemaining` before every payout is claimed needs `block.timestamp > effectiveClaimDeadline`. Tests `test_refundWaitsUntilAfterClaimDeadline`, `testFuzz_claimWindowBoundary` in `test/AgonPrizeVault.Fuzz.t.sol` |
